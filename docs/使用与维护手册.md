## 选择迁移方式

| 内网用途 | 在外网电脑上复制什么 | 复制后做什么 |
| --- | --- | --- |
| **只安装和使用** | 复制 `offline/0.11.15/dsh-mcp-tbea-knowledge-win-x64.zip` | 在 Windows x64 内网电脑解压或安放目录，初始化、安装到匠宝、配置正式知识库 |
| **继续改代码、调试、编译和打包** | 复制整个 `F:\股份公司ai平台\dsh-mcp-tbea-knowledge` 源码项目，带上 `node_modules`、`package-lock.json` 及 `offline` 中的附带运行时 | 推荐放在单独的开发目录。既可从源码构建，也可用同一次迁移中的离线包做安装测试 |

`offline` 是**打包输出目录**。可部署最新打包的运行目录，也可将该目录压缩后交付。运行目录包含编译好的 MCP、插件、安装脚本、配置示例、手册、Windows x64 Node.js 运行时。PDF.js 和 Excel 解析组件随插件一起安装。Word 和 PPT 使用匠宝内置转换服务。源码工程的 `src`、`plugin/src`、`tests` 和开发用 `node_modules` 用于开发。

匠宝 `desktop` 使用离线包内的完整 `plugin` 目录安装。源码根目录的构建产物也可用于普通 Profile 和独立 MCP。

离线包提供的是**知识库插件和 MCP**。内网电脑应已安装匠宝，正式使用还需要能访问 `ai.tbea.com`、有权访问知识库的 AK/SK 和项目 ID，以及已配置好的内网 DeepSeek 模型。演示模式可以先验证本地运行和展示链路。

匠宝 `desktop` 的配置在 Harness 根目录。独立 MCP 和普通 Profile 使用运行目录内的 `config/local.json`。

## 安装与升级

### 匠宝 `desktop` Profile

1. 解压 Windows x64 通用离线包。正式部署时，管理员直接打开解压包中 `plugin\config\example.json`，按[正式环境配置](#正式环境配置)填写 `mode: live`、公司 AK、SK 和 Project ID 等值。`serviceToken` 留空即可自动生成。原样安装通用包会使用演示模式。
2. 在匠宝「插件管理」中添加同一份 `plugin` 目录并启用。首次启用时，插件校验模板并在实际 `DSH_HOME` 下自动创建 `dsh-mcp-tbea-knowledge.json`，Windows 默认是 `%APPDATA%\dsh-desktop\harness`。已有配置会继续使用。关闭旧版手动服务，从托盘完全退出并重新打开匠宝。
3. 执行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Doctor.ps1 -Desktop`，核对插件版本、配置位置、`Runtime identity OK` 和 `MCP handshake OK`。使用自定义位置时，诊断也传入相同的 `-HarnessHome`。诊断同时显示 PDF.js 状态、外部 Office 程序路径和知识库诊断文件的位置。
4. 在输入框使用 `/公司知识库`，或通过 `+` 菜单选中「公司知识库」，提问并从参考来源或知识库目录打开 PDF。演示模式可访问 `http://127.0.0.1:17861/demo`。

| 安装后的位置 | 用途 |
| --- | --- |
| `harness\dsh-mcp-tbea-knowledge.json` | 固定的知识库配置。 |
| `harness\profiles\desktop\node_modules\dsh-plugin-tbea-knowledge` | 匠宝管理的插件入口。使用版本目录的匠宝会将其指向 `profiles\.generations\live` 中的实际版本。 |
| 实际 Harness 内的 `logs\dsh-mcp-tbea-knowledge.jsonl` | 知识库检索和原文预览诊断。 |
| 匠宝安装目录内的 LibreOffice Kit | 由匠宝随应用提供，供知识库插件在 Host 进程内转换 Word 和 PPT。 |
| `harness\dsh-mcp-tbea-knowledge-data` | 未指定 `dataDirectory` 时使用的插件数据目录。 |

按公司统一下发的流程，管理员验证首次启用成功后，可将完整 `harness` 和 `win-unpacked` 一起下发。员工把 `harness` 放在自己账号对应的位置即可使用已有配置。通用 ZIP 只有配置模板。准备后的内网部署副本和其中的已安装插件目录含有公司配置，随 `harness` 通过公司允许的方式下发。

如需安装前直接写配置，仍可执行 `Initialize.ps1 -Desktop -ConfigSource <配置文件路径>`。该命令默认使用终端的 `DSH_HOME` 或 Windows 默认目录，可通过 `-HarnessHome` 指定实际绝对路径。要主动更新已有的 Harness 配置，追加 `-ReplaceConfig`。已有的 `0.11.9` 部署副本如果包含 `plugin\desktop-deployment.json`，首次启用时仍优先读该文件。导入旧模板时会去掉已退役的图片预览程序字段，自定义相对路径按目标 `harness` 解析。

### 升级或卸载重装

管理员用新版离线包中的 `plugin` 目录更新同名插件，重启后用 `Doctor.ps1 -Desktop` 核对实际版本。若匠宝本地插件界面只提示「已安装」且没有替换入口，在匠宝中卸载旧版后安装新版。首次从显式 `configFile` 的旧版迁移到新布局时，可以用旧配置准备内网部署副本，或直接运行 `Initialize.ps1 -Desktop` 导入。若 Profile 有手动写入的 `configFile` 覆盖，确认它仍有意使用旧路径，或在管理员配置中移除该覆盖以启用根目录布局。

### 普通 Harness Profile 与独立 MCP

在提供 `dsh` 的终端运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Install-Plugin.ps1 -Profile web`，将 `web` 替换为实际普通 Profile。脚本会生成旧式的显式 `configFile`，本地配置仍在该运行目录的 `config\local.json`。独立运行使用无参数的 `Initialize.ps1` 和 `Start-Service.ps1`，诊断使用无参数的 `Doctor.ps1`。这两种方式继续依赖原运行目录，搬迁后按原有方式重新初始化。

## 正式环境配置

1. 从托盘完全退出匠宝。若 MCP 曾单独启动，也在原窗口停止服务。
2. 打开匠宝实际 Harness 根目录下的 `dsh-mcp-tbea-knowledge.json`，默认位置为 `%APPDATA%\dsh-desktop\harness`。普通 Profile 或独立 MCP 则打开运行目录内的 `config/local.json`。
3. 对照下面的片段，逐项修改同名字段。**这是需要更新的字段示例**。在已有文件中修改对应项，保留初始化生成的 `serviceToken`、端口、数据路径和其他设置。填写 AK/SK 时使用已获知识库访问授权的那组凭证。

~~~json
{
  "mode": "live",
  "autoRetrieveKnowledge": true,
  "knowledgeDirectory": { "mode": "auto", "refreshSeconds": 60 },
  "platform": {
    "baseUrl": "https://ai.tbea.com",
    "accessKey": "填写现有 AK",
    "secretKey": "填写现有 SK",
    "projectId": "填写项目 ID",
    "rerankModelName": "bce-reranker-base-v1",
    "rankScoreThreshold": 0.4
  }
}
~~~

`autoRetrieveKnowledge` 位于知识库配置文件的最外层。省略时默认为 `true`，模型可按需查库。仅手动选中「公司知识库」后才查库时，请设为 `false`，已有的 `false` 可以直接保留。 [设置按需查库或仅手动查库](#设置按需查库或仅手动查库)

4. 保存后重开匠宝，再执行 `Doctor.ps1 -Desktop`。输出应包含 `mode: live` 和两个 MCP 工具。诊断通过后在匠宝选择「公司知识库」，发送一条已知可命中的问题，例如此前国别手册的乌拉圭原文。展开「参考来源」，确认能看到目标文档和切片。诊断只确认本机 MCP，实际提问才验证平台权限和检索。

- **自动发现**：`projectId` 使用平台项目 ID。MCP 分页获取该凭证在项目中可见的库，目录默认 60 秒到期，由下次访问触发刷新。新库完成授权和索引后即可随目录刷新加入。请先确认凭证能访问的库都适合向这台电脑的使用者开放。
- **手工限定**：将 `knowledgeDirectory.mode` 设为 `static`，在同一配置的 `knowledgeBases` 数组中填写至少一个真实的 `{"id":"真实库 ID","name":"显示名称"}`。库 ID 来自目录响应的 `data[].id`。已有静态清单的旧配置没有显式模式时会继续使用静态范围，要自动接入新增库须显式改成 `auto`。
- **平台要求**：知识库检索使用 AK/SK 签名，`rerankModelName` 必填。聊天应用的 `app_id` 和 API Key 无需填写。普通图片若需 Bearer 鉴权，可配置 `platform.assetAuth: "bearer"` 和 `platform.assetApiKey`。预签名图片按原签名请求。

### 检索参数

| 配置 | 默认值 | 含义 |
| --- | ---: | --- |
| `retrieval.perLibraryTop` | 3 | 每个库最多返回的候选数，也受工具本次 `top` 约束 |
| `limits.top` | 10 | 工具未传 `top` 时使用的默认上限 |
| `limits.maxEvidenceChunks` | 5 | 合并去重后最多提供给模型的证据数，有几条合格证据就使用几条 |
| `platform.rankScoreThreshold` | 0.4 | 平台召回阈值 |
| `retrieval.evidenceScoreThreshold` | 默认沿用平台召回阈值 | 本地接受证据的最低分，可单独设置为 0～1 |
| `retrieval.libraryTimeoutMs` | 8000 | 单库请求发出后的超时，单位毫秒 |
| `retrieval.roundTimeoutMs` | 30000 | 整轮超时，涵盖目录、排队和平台请求，单位毫秒 |

正式模式按库单独请求，服务级并发为 2，请求发起间隔至少 150 毫秒。问题明确时会按主题匹配库名和描述，优先查相关授权库。证据不足时扩展至其他授权库，并在同一轮总时限内用同义说法补查。结果会区分「优先查库」与「部分库未完成」。当前使用平台内置 Reranker，跨库排序和阈值需按业务样例校验。

### 检查检索证据与校准阈值

新增制度库授权并完成索引后，可以直接用员工平时的问法测试。例如「工牌丢了怎么补」应能找到正文里的「员工证件遗失补办」，并核对适用对象和办理流程。插件先查原问题。只有本地规则无法确认足够证据时，才复用匠宝当前会话已确认的内网模型复核候选。需要补查时保留原问题，再加入改写后的检索词；补查返回的新切片可以再复核一次。辅助过程共用最多 10 秒和现有的整轮检索时限。

语义复核默认可用，实际调用取决于匠宝是否托管知识服务、当前模型路由能否识别为内网，以及是否需要复核。插件识别配置中明确的 HTTPS 公司域名、内网 IP 或回环地址。其他 HTTPS 内网模型域名可由管理员在 `retrieval.semanticModelOrigins` 中登记完整来源，例如 `https://model.example.internal`。可设 `retrieval.semanticReview: false` 关闭辅助调用。独立 MCP、无法确认的路由或辅助超时继续按已有检索流程返回证据。

同义词配置是可选的。管理员仍可在 `retrieval` 中加入特定内部术语。例如下面的设置适用于合同场景。

~~~json
{
  "retrieval": {
    "diagnostics": true,
    "synonyms": [
      { "term": "印章使用", "aliases": ["盖章"], "context": ["合同"] }
    ]
  }
}
~~~

保留原有 `retrieval` 项，将需要的字段合入原对象。`term` 是正式短语，`aliases` 是同一业务的其他说法，`context` 限定生效语境。正式模式的候选切片诊断默认开启，已有配置省略该字段时也生效。管理员可以设 `retrieval.diagnostics: false` 关闭。

按 `tbea-retrieval`、会话 `sessionId` 或来源快照 `searchId` 查询日志。Windows 匠宝默认日志为 `%APPDATA%\dsh-desktop\harness\logs\dsh-mcp-tbea-knowledge.jsonl`，自定义 Harness 使用实际 `DSH_HOME\logs`。勾选公司知识库后的预检索还会记录该轮 `messageId`。独立 MCP 默认使用数据目录下的 `logs`。

- `libraries` 按阶段和库显示平台返回量、范围过滤、每库取数上限、排序分数和失败类别。平台返回的切片使用 `hits` 对照。每次请求最多记录前 40 个平台条目，返回总数仍完整记录。在授权库范围内同时记录平台提供的文档名。
- `candidates` 记录插件对候选的筛选结果。常见原因包括 `below-threshold`（低于插件阈值）、`no-topic`（与所问事项不符）和 `result-limit`（超过证据数上限）。`semantic` 显示有无复核、改写补查或澄清。
- `projection` 记录入选切片在构造模型上下文时的结果。`sent` 和 `sent-related` 表示已提供给模型，后者是背景证据。`rejected-after-truncation` 表示正文截断后未达到证据要求。对照 `selected` 和 `sent` 可识别这一步的变化。若模型已经收到切片，仍需查看回答判断是否实际使用。会话没有调用知识检索时，该轮没有 `tbea-retrieval` 记录。

正式检索日志的 `candidates` 包含切片 ID、文档名和原文片段。每轮最多记录 100 条正文片段，每条最多 1,600 字符。片段保留换行和表格内容，`excerptTruncated` 标记截断。日志会屏蔽链接、配置中的凭据及常见带标签的凭据，按含内部片段的文件保管。将 `retrieval.diagnosticExcerpts` 设为 `false` 可只记录文档名、切片 ID、分数和判断原因。日志达到 10 MiB 时轮换并保留上一份。

自动查库和程序预检索使用同一套规则。服务端先检查平台返回的数值型 `rank_score`，再核对切片正文与表格是否匹配所问事项。问题中的国家或完整标准编号会用正文和文件名核对。多事项问题优先为不同事项保留证据。`perLibraryTop` 和 `maxEvidenceChunks` 都是上限，证据不够时允许返回 0 条。

模型工具结果的 `totalCount` 是各库实际返回的候选数，`hitCount` 是送入模型的证据数。`evidenceStatus` 提示匹配、部分匹配、没有证据，或本次无需查库。可识别的多事项问题还会返回 `missingTopics`。`matched` 表示通过本地分数和文字检查，模型仍须核对正文是否直接支持具体结论。同义改写、型号简称、图片里的文字以及切片不完整都可能导致漏检，复测可把产品、国家、标准编号和所问参数明确写入问题。

保持 `platform.rankScoreThreshold` 为 `0.4`，可以在已有知识库配置的 `retrieval` 对象中单独增加 `"evidenceScoreThreshold": 0.45` 进行试验。低于平台召回阈值的本地配置无法找回平台已经过滤的切片。每次修改后完全退出并重开匠宝。使用同一批问题分别测试 `0.40`、`0.45`、`0.50`、`0.55`，记录正确资料是否召回、错库切片是否被过滤、缺少依据时回答是否说明。若正确切片从未进入候选，先在同一查询下检查平台返还内容及 `perLibraryTop`。公司正式阈值应根据内网测试结果决定。

| 验收场景 | 核对结果 |
| --- | --- |
| 未选库，问 `2 + 2 等于几？` | 直接回答，模型即使误调用 MCP，也不会请求公司平台 |
| 搜索乌拉圭国别手册的原段落 | 返回正文匹配的国别手册切片，费用报销制度不进入回答 |
| 问某国家的电压和绝缘，样本只提供电压 | 仅引用有依据的部分，并指出绝缘要求缺少资料 |
| 询问当前库没有收录的公司制度 | 说明未找到能支持结论的公司资料 |
| 手动选中「公司知识库」后提问 | 继续由程序先检索，引用仅展示通过检查的证据 |

### 设置按需查库或仅手动查库

编辑当前知识库配置，在最外层加入或修改 `autoRetrieveKnowledge`。填写 JSON 布尔值 `true` 或 `false`，不要加引号。下面以仅手动查库为例，只展示需要配置的字段。

~~~json
{
  "autoRetrieveKnowledge": false
}
~~~

| 配置值 | 未选中「公司知识库」时 | 已选中时 |
| --- | --- | --- |
| `true`（默认） | 可直接提问。模型判断是否需要公司资料，并按需调用知识库 | 程序先检索，再交给模型回答 |
| `false` | 插件不向模型提供知识库工具，本轮不会自动查库 | 通过 `+`、`/` 菜单或 `/公司知识库` 选中后，由程序先检索。标签在当前会话持续生效，直到取消 |

保存后从托盘完全退出并重开匠宝。运行 `Doctor.ps1 -Desktop`，根据 `DSH knowledge retrieval: on-demand` 或 `manual-only` 确认配置值。旧配置省略此项时按 `true` 处理。此项控制匠宝插件给模型提供的知识库工具，服务是否随匠宝启动仍由 `service.autoStart` 控制。切换为手动模式后仍可打开历史来源，也可手动刷新切片详情。

### 在平台维护知识库主题

正式环境使用自动目录且开启按需查库时，在股份公司 AI 平台维护库名和描述。建议写清覆盖对象、典型资料和适用范围，例如将「采购资料」描述为「采购业务的供应商准入、复审及提交材料」。平台只返回库名时，摘要会用库名作为主题线索。静态模式使用本地 `knowledgeBases` 指定的范围，描述可填写在对应条目的 `description` 字段。

插件启动后在后台加载摘要，与检索共享同一份授权目录。检索工具说明最多附加 12 个条目，主题 JSON 最多 1600 字符，只包含库名和简短描述。新增、改名、修改描述或变更授权，在下一次完整目录刷新后生效。冷启动、目录过期或刷新失败时，当前请求沿用通用查库规则；过期摘要停止附加到新的工具说明。

模型先判断答案是否依赖公司资料，再参考目录主题。查库仍覆盖授权范围。回答里的公司规定、流程和数值应引用实际切片。关闭按需查库时，插件只在手动选中后检索，后台也不加载用于模型判断的摘要。

## 提问与查看来源

| 使用方式 | 行为 |
| --- | --- |
| 点击 `+` 或输入 `/` 后选择「公司知识库」，也可输入 `/公司知识库` 后按回车 | 此会话的每条新文字提问先查库，再交给模型。标签持续到手动取消 |
| 未选中或已取消标签 | 按 `autoRetrieveKnowledge` 设置执行。开启时，模型通常直接回答纯数学或通用翻译，涉及公司标准等问题时按需查库。关闭时，须先手动选中才会检索 |
| 停止本次查库 | 使用 DSH 的停止按钮。移除标签只影响之后的提问 |

`@` 用于 DSH 的文件、目录和会话引用。追问时尽量带上产品型号、地区或适用的标准版本。

打开「参考来源」可复制切片、查看表格和图片。继续同一轮时，模型补充查库找到的来源会在回答下方的「补充检索」中显示。展开「切片详情」能查看当前记录，刷新按钮会重新获取平台详情。等价切片的出处可在「其他来源」分别打开。图片随来源展开加载，支持预览、放大及下载。模型收到切片正文、表格文字和引用编号。

部分库未完成时，卡片显示已查询库数，模型使用已取得的证据并说明覆盖范围。全部库完成但无相关结果时提示缺少依据。目录失败、全部库失败或用户停止时，强制模式结束本轮处理。平台错误后可手动重新发送问题。

### 会话引用文档

- 在会话顶部选择「引用文档」。窗口较窄时，可在会话顶部的更多菜单中找到它。列表汇总当前会话各轮保存的公司知识库来源，手动预检索和模型按需查库都会计入。
- 同一知识库里的同一份文档只显示一次。点击文档名打开原文预览，点击「查看引用」回到对应轮次。如果文档在多轮出现，先选择要跳到哪一轮。
- 有明确原文标识及版本的跨库副本会合并展示，保留库名和各轮引用。正文用到的文档标为「正文已引用」。点击正文里的知识库引用链接会核对该轮引用与快照权限，先展开对应切片和同次检索的参考来源。需要全文时点「查看原文」。
- 在对话中展开每轮的「参考来源」，可查看原始切片、表格和图片。历史快照缺失、无权限或缺少文档标识时，汇总保留能够读取的文档并提示部分来源不可用。原文预览仍以当前知识库权限和格式支持为准。

## 知识库目录与原文预览

### 使用方法

1. 点击匠宝左侧工作区上方的「知识库目录」。主区域打开独立页面。
2. 选择一个知识库，可用「搜索文档名称」筛选。目录显示文件名和格式。打开文档可查看已返回的大小、创建日期、状态。
3. 在预览区域向下滚动阅读。文档页按顺序追加，优先渲染首页，靠近当前视口的页才继续渲染。点左箭头返回目录，窄窗口中目录与预览轮流占用主区域。
4. 看到「平台目录未取全」时，可用列表中已经取得的记录，并点击「重试」。网关按每次 100 份自动续取，100 份是接口每次取数大小。内网联调曾遇到平台提供游标后却返回空列表，界面会显示已取数量，待平台接口正常后再验证实际超过 100 份的库。

### 文件类型与转换方式

| 转换方式 | 格式 | 查看效果 |
| --- | --- | --- |
| PDF.js | `pdf` | 按原页连续展示 |
| 匠宝内置转换和 PDF.js | `doc`、`docx`、`ppt`、`pptx` | 按页或幻灯片连续展示，字体和复杂对象取决于已安装字体和转换引擎 |
| 只读工作表 | `xls`、`xlsx` | 切换工作表，滚动查看，显示中文、数字、日期、合并单元格及公式已有的结果 |
| 浏览器直接展示静态内容 | `txt`、`md` | 显示正文、标题、列表、表格和内嵌图像 |
| 静态内容处理后由已配置的外部程序转换 | `html`、`mhtml` | 显示正文、标题、列表、表格及能从文件内取得的嵌入图片。网页样式会简化，脚本和外链资源会被移除 |
| 已配置的外部程序转换 | `png`、`jpg`、`jpeg`、`bmp` | 显示图像预览页 |
| 专用转换程序 | `wps`、`dps`、`dpsx` | 按格式配置转换程序后可预览，缺少组件时仍可查看目录、检索结果和切片 |

LibreOffice 的格式和过滤器可以参考其[官方转换过滤器表](https://help.libreoffice.org/latest/en-US/text/shared/guide/convertfilters.html)。OFD 由公司选定的内网组件转换，需检查公司所用样本的图像、字体和版式。

### 在内网启用原文预览

1. 确认插件已生成或导入正式配置，按前文配置 `mode: live`、`projectId`、AK/SK、知识库授权范围。先重启匠宝确认目录能显示库和文档。
2. 新装模板中的 `documentPreview.enabled` 和 `documentPreview.allowPdfViewer` 默认都为 `true`。升级安装会继续使用已有配置，管理员可手动开关。旧配置省略预览段或其中的开关时，运行时也默认开启。任一开关明确设为 `false` 都会关闭原文预览。自定义转换程序的相对路径以当前配置文件所在目录为准。

```json
{
  "documentPreview": {
    "enabled": true,
    "allowPdfViewer": true
  }
}
```

3. Word 和 PPT 优先使用按格式显式配置的 `documentPreview.converters`。其次使用匠宝 Host 内置服务。普通 Profile 和独立 MCP 可以通过 `documentPreview.office` 指定兼容 LibreOffice 命令行的外部程序。所用程序路径以配置文件所在目录解析。
4. 如果 OFD 或 WPS 系列需专用程序，在 `converters` 填入对应扩展名和包装程序路径，例如 `"converters": { "ofd": "D:/工具/ofd-to-pdf.exe", "dpsx": "D:/工具/dpsx-to-pdf.exe" }`。该程序接收两个参数，依次为输入文件绝对路径、输出 PDF 绝对路径，应在退出前写完 PDF。先用普通样本确认命令生成正确的 PDF，再替换内网真实样本。同样可以对 Word、PPT 设置专用程序。`officeToPdf` 由匠宝在运行时提供。
5. 从托盘完全退出匠宝并重新打开。先测试一份短 PDF，再验收已配置的其他文件格式。首次打开需等待从平台读取和转换，后续按滚动位置渲染 PDF 页。

### 预览进度与权限说明

界面分别显示下载、转换、排版、读取工作表和加载首页。原件响应提供可信大小时显示下载百分比。转换和首屏加载显示动态进度与耗时。同一文档的并发打开共用一次处理。闲置十分钟内重新打开时仍会核对授权和原件字节，内容一致可复用转换产物或工作表原件。Excel 在浏览器重新解析，首张工作表可以查看后结束等待。

PDF 与 Excel 均通过鉴权接口分段读取。Excel 在浏览器 Worker 中解析，原件上限 50 MiB，XLSX 展开上限 128 MiB，工作簿至多 64 张表、每张 2 万行及 256 列、合计 50 万个有值单元格和 400 万字符。工作表以每组 50 行显示，可翻组并横向和纵向滚动。日志 `DSH_HOME/logs/dsh-mcp-tbea-knowledge.jsonl` 记录准备阶段、缓存复用、表格解析及首屏结果。更改 `documentPreview.allowPdfViewer` 后，从托盘完全退出并重新打开匠宝以生效。

### 定位原文预览耗时

先筛选 `tbea-preview-prepare`。`timing` 显示插件排队、读取详情、下载和转换的总耗时，`authorizationMs` 是打开时检查库访问权限的耗时。`sourceBytes`、`pdfBytes`、`converter` 与 `cached` 可用于比较同一文档的不同打开记录。

- `detailTiming` 中的 `download-headers` 是等待平台响应头的耗时。`download-body-and-write` 包含网络传输、写临时文件和计算需要的内容指纹。
- 匠宝转换时，`office-await-source` 是提交转换到收到源读取回调的耗时。`office-read-source` 是读取原件并核对指纹的耗时。`office-after-read` 是回调结束到服务返回的时间，包含服务内部等待、引擎处理和取回 PDF。`office-service-total` 含上述耗时。`office-without-source` 表示该次调用未触发源读取。对外部转换器可看 `external-process`，以及准备输入、验证和落盘等步骤。
- 用 `previewId` 对照 `tbea-preview-first-page`。`pdfAssetMs` 是加载 PDF.js 模块的时间，`pdfLoadMs` 包含启动查看器、分段取 PDF 和文档解析，`pdfRenderMs` 是文档就绪到首页绘制完成的时间。Excel 的 `tbea-preview-first-sheet` 仍提供 `parseMs`。预览耗时日志只记录诊断标识、数字和错误类别。

### 权限和排错

- 目录和原文预览沿用知识服务的项目目录和静态授权范围，经匠宝 Connection 的同源接口访问，仅 Owner 有权调用。局部网关启用预览时只从 `https://ai.tbea.com` 读取同源原件，无跨域回退。预览页经鉴权传输，界面没有原件下载入口。
- 转换在知识服务进程所在机器执行。原件和中间文件存于该进程使用的系统临时目录，到期或正常关闭时清理。清理周期为一分钟，闲置十分钟过期。若要防止员工访问原件，应由管理员在受控机器运行转换服务，并隔离 AK/SK 和临时目录权限。个人模式下本机管理员可以访问本机文件；阅读者也可以截取看到的页面。
- 「原文预览未启用」表示 原文预览开关已关闭。「待配置专用转换组件」表示对应扩展名缺少专用程序。「内置 Word/PPT 转换不可用」表示当前环境缺少匠宝转换服务及管理员配置的备选程序。「未提供可用的同源原文地址」表示平台的详情和目录均未给出可用地址，可用正式内网环境复测 `DescribeDocument` 和 `DescribeDocuments`。
- 普通网页只显示静态内容。密码保护、损坏或超出平台标注大小限制的文档会报告转换错误。支持至 3000 页，用户可以重试；个别签名链接失效时，重新打开会请求平台刷新地址。

## 内网开发与打包

### 复制开发工程

1. 从外网电脑复制完整源码项目。建议在内网放到例如 `F:\Dev\dsh-mcp-tbea-knowledge`，与日常使用的 `F:\Apps\dsh-mcp-tbea-knowledge` 分开。若只复制了离线 ZIP，需要再迁移源码和开发依赖。
2. 在开发目录确认有 `package.json`、`package-lock.json`、`tsconfig.json`、`src`、`plugin/src`、`scripts/build.mjs`、`tests` 和现有的 `node_modules`。需要无系统 Node 的开发方式时，带上 `offline/0.11.15/dsh-mcp-tbea-knowledge/runtime/node.exe`。当前复制的开发依赖适用于 Windows x64，同平台且依赖完整时可直接构建。
3. 有系统 Node.js 与 npm 时执行 `node --version` 和 `npm --version`。本项目要求 Node.js **24.9.0 或更高版本**。无 npm 时可用下文附带的 Node 编译和跑测试。离线环境已有完整 `node_modules` 时，直接使用这份依赖。缺失依赖或修改了依赖版本时，在能获取依赖的同平台环境准备好再迁入。

### 构建、测试与调试

从**开发目录**执行以下命令。服务端 TypeScript、插件 Host 和浏览器代码都会被打包。修改 `src` 或 `plugin/src` 后重新构建，才会更新服务和插件加载的产物。

~~~powershell
Set-Location -LiteralPath 'F:\Dev\dsh-mcp-tbea-knowledge'
npm run typecheck
npm run build
npm test
~~~

`npm run typecheck` 严格检查服务端 `src/**/*.ts` 和插件 `plugin/src` 中的 `.ts`、`.tsx` 文件。`npm run build` 会先做同样的类型检查，再用 esbuild 更新 `dist` 和 `plugin/lib`，正常结束显示 `Build complete`。`npm test` 也会验证构建后的 Host，所以先构建再跑测试。测试使用本机 `127.0.0.1`，平台及业务数据由模拟接口提供。若系统未装 npm，可使用附带的 Node 和已迁入的 `node_modules` 执行对应脚本。

~~~powershell
$portableNode = '.\offline\0.11.15\dsh-mcp-tbea-knowledge\runtime\node.exe'
& $portableNode --version
& $portableNode .\node_modules\typescript\bin\tsc --noEmit
if ($LASTEXITCODE -ne 0) { throw 'TypeScript 类型检查失败' }
& $portableNode .\scripts\build.mjs
if ($LASTEXITCODE -ne 0) { throw '构建失败' }
& $portableNode --test 'tests/*.test.mjs'
~~~

需要检查网页交互时，可执行 `npm run test:ui`。如只需检查会话历史汇总、点击文档名预览和按轮次跳转，可单独执行 `npm run test:citations-ui`，这项测试使用模拟会话和响应。先准备 Playwright 能使用的 Chromium，也可用环境变量 `TBEA_TEST_BROWSER` 指向现有的兼容浏览器可执行文件。演示页测试的截图写到 `test-results`。

在开发目录用源码构建结果联调普通 Profile 时，可先执行旧式初始化，再把安装来源指向该目录的 `plugin`。联调匠宝 `desktop` 时使用离线包装配好的 `plugin` 目录。用开发配置做模拟或正式联调，完成后从托盘完全退出并重开匠宝。开发与日常运行要分别核对配置和数据路径。两份服务同时运行时使用各自的本地端口。

1. 在开发目录用 Windows x64 的 Node.js 和 npm 执行下方命令。打包脚本从当前 Node.js 安装目录取 `node.exe` 和 `LICENSE`，使用独立安装的运行时来打包。

## 后续开发与维护

### 修改位置速查

请求从匠宝进入插件 Host，由 Host 调用本机 MCP。MCP 读取项目授权目录，逐库查询股份公司 AI 平台，然后把切片整理成两份数据：一份给模型作为文字证据，一份通过本机受保护的接口供界面展开引用。查不到资料或请求取消时，沿这条链路逐层定位。

| 想修改的内容 | 代码位置 | 修改后重点检查 |
| --- | --- | --- |
| 配置字段、默认值、旧配置兼容 | `src/config.ts`、`src/contracts.ts`、`config/example.json` | 新配置和旧配置都能启动，正式凭证字段仍只留在本机配置 |
| 平台地址、签名、分页、检索响应或图片请求 | `src/platform.ts` | 用模拟响应验证，再到内网验证原始响应字段、分页、权限和图片 URL |
| 查库范围、引用详情、来源权限、目录摘要 | `src/knowledge.ts`、`src/catalog-summary.ts` | 篇目或库权限撤回后，旧来源再次打开时仍受校验 |
| 召回数量、超时、分数、去重 | `src/retrieval.ts`、`src/gate.ts` | 乌拉圭原文、不同版本、部分失败、取消和低相关结果 |
| 切片正文、Markdown 表格、HTML 表格、图注 | `src/normalize.ts` | 样例中的工程符号、合并单元格、表格文字、图片与模型文字分离 |
| 历史引用快照和本地图片缓存 | `src/store.ts`、`src/contracts.ts` | 用旧版快照启动新版，检查旧引用、错误提示及缓存容量 |
| MCP 工具入口、健康与诊断协议 | `src/server.ts`、`src/runtime.ts` | 用构建后的 `Doctor.ps1` 及客户端检查版本和工具握手 |
| 匠宝工具注册、按需查库提示、手动选择 | `plugin/src/host.mjs`、`catalog-hint.mjs`、`selection.mjs`、`composer.mjs` | `autoRetrieveKnowledge` 开关、`+` 菜单及 `/公司知识库` 命令 |
| 参考来源卡片、图片和表格样式 | `plugin/src/client.jsx`、`plugin/src/style.css` | 窄窗口、深色和浅色主题、键盘操作、图片预览 |
| 会话引用文档、轮次跳转和原文预览 | `plugin/src/cited-documents.ts`、`plugin/src/cited-documents-view.tsx`、`plugin/src/library-browser.tsx` | 历史翻页、文档去重、权限变化、预览和回到引用轮次 |

会话文档汇总、目录和原文预览已纳入严格 TypeScript 检查。内部快照和公开快照在 `src/contracts.ts` 中分别定义。插件读取历史事件和 HTTP 快照时校验实际字段，维护旧会话兼容性。插件 Host 和其他界面模块可沿用现有接口逐步迁移。

### 一次日常改动怎么做

1. **把问题分层。** 如果平台原始返回缺字段，在 `platform.ts` 处理；如果平台已经返回但文本、图片或表格未显示，先看 `normalize.ts` 和引用卡片组件；如果压根没查库，先检查开关、工具注册及匠宝的调用记录。
2. **用脱敏样例在开发目录复测。** 从正式平台留取最小复现，只保留需要验证的字段，去除凭证、签名链接和敏感资料。服务默认可用 `mock` 模式在本机验证，正式验证使用单独的内网配置。
3. **先定义数据边界，再改业务实现。** 公共结构放在 `contracts.ts`。处理配置、HTTP 或平台 JSON 时先把输入视为 `unknown`，再检查结构。项目内的 TypeScript 本地导入使用明确的 `.ts` 后缀，类型专用导入使用 `import type`。直接从源码运行的 Node 依赖可擦除的类型语法，例如用联合类型代替需运行时转换的 `enum`。
4. **保持旧数据可读。** 修改引用结构时，先检查 `tbea-snapshot/v1` 快照和匠宝工具结果。新增字段优先做成可选并提供回退。确需更改协议版本时，同步调整服务、Host 和展示端，增加一条旧配置或旧快照的回归用例。
5. **按改动范围运行验证。** 日常先跑 `npm run typecheck`、`npm run build`、`npm test`。修改界面再跑 `npm run test:ui`。发布前运行 `npm run pack:offline` 和 `npm run test:offline`。
6. **在内网做最小实机验收。** 安装新包后检查本机握手，用一条关键业务问题确认切片来源，另测一条普通问题、一次手动查库及一条旧引用。

### 调试时常见问题

| 现象 | 优先检查 |
| --- | --- |
| 运行时仍是旧逻辑 | 用 `Doctor.ps1 -Desktop` 确认匠宝加载的是这次构建的插件和预期的配置。完全退出后再打开 |
| 缺少 `tsc`、`node_modules` 或 esbuild 可执行文件 | 确认进入源码根目录，开发依赖完整且为 Windows x64。类型检查也可用前文的附带 Node 命令 |
| 本机接口可访问，但匠宝不查库 | 看 `Doctor.ps1` 中是 `on-demand` 还是 `manual-only`。选中标签再问已知问题，区分模型未调用与服务未返回 |
| 目录已改，模型工具说明仍未显示新主题 | 核对 `knowledgeDirectory.mode` 和 AK/SK 对应项目。自动模式等下次目录刷新，空描述时只返回库名。背景请求还没完成时可用手动选择确认检索 |
| 修改类型后报出内外部结构不一致 | 从错误指向的字段沿 `contracts.ts`、平台解析、数据快照和 MCP 输出逐层检查，补充数据校验或兼容映射 |
| 历史来源显示快照格式无效 | 备份该快照并检查 JSON、版本和引用结构。新生成的回答会有独立快照，打开历史来源仍需对应的旧文件及当前权限 |

### 版本、备份和交付

每次更新安装包时，同步检查项目与插件的 `package.json`、`package-lock.json` 和 `src/runtime.ts` 中的版本。匠宝插件通过插件管理切换版本。回到旧版的显式配置布局时，按该版本的安装说明准备相应配置。

## 服务管理与排错

默认地址为 `127.0.0.1:17861`。匠宝托管的 MCP 随匠宝完全退出而停止。独立运行的 MCP 由管理员单独维护。

| 操作 | 在 PowerShell 中执行 |
| --- | --- |
| 检查匠宝插件版本、配置身份和 MCP 握手 | `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Doctor.ps1 -Desktop` |
| 暂停本次匠宝托管的 MCP | `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Stop-Service.ps1` |
| 停止手动运行的 MCP | `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Stop-Service.ps1 -Manual`，也可在原窗口按 `Ctrl+C` |
| 关闭随匠宝启动 | `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Set-ServiceAutoStart.ps1 -Mode Disable`，然后完全重启匠宝 |
| 恢复随匠宝启动 | `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Set-ServiceAutoStart.ps1 -Mode Enable`，然后完全重启匠宝 |

如需独立运行，使用 `Start-Service.ps1`。匠宝可复用版本和配置一致的手动服务。同一个端口只需启动一份服务。使用其他支持 HTTP MCP 的客户端时，可连接 `http://127.0.0.1:17861/mcp`，使用 `Authorization: Bearer <serviceToken>`。同一 DSH Profile 应只注册一份 `mcp__tbea__` 工具。

| 现象 | 处理方法 |
| --- | --- |
| 找不到 `dsh` 或 CLI 拒绝修改 `desktop` | 从匠宝托盘打开终端。匠宝专用 `desktop` Profile 通过其插件管理入口操作 |
| 安装报 `not-a-bundle` 或安装后仍加载旧插件 | 确认离线包内完整的 `plugin` 目录和随包的 `plugin/cordis.patch.yml`，核对当前 Profile，从托盘完全退出后再打开 |
| 提示旧服务、端口占用或配置不匹配 | 先核对监听者、版本和实际使用的配置文件。停止对应旧实例再重启。多个独立 Host 使用不同的端口及数据目录 |
| 提示 JSON 错误、缓存路径不可写 | 检查 `local.json` 的英文引号、逗号和括号，确认 `dataDirectory` 指向可写目录。修复后可点击「重试启动知识服务」 |
| 目录为空、分页失败或平台鉴权失败 | 核对 AK/SK、项目 ID、授权范围，确认当前插件读取的是正确配置 |
| 内网 HTTPS 证书报错 | 按公司环境配置 `NODE_EXTRA_CA_CERTS` 指向受信的公司 CA 证书，然后重启 |
| 来源图片显示失败 | 展开来源后重试图片，必要时先刷新切片详情。有预签名的图片链接过期时会尝试刷新 |

诊断工具在正式模式仅检查本地服务及 MCP 握手。启动重试只恢复服务，先前失败的问题由用户重新发送。

## 卸载与清理数据

- **匠宝 `desktop` Profile**：从匠宝插件管理中卸载知识库插件，再从托盘完全退出并重启。
- **普通 Harness Profile**：在相应终端运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Uninstall-Plugin.ps1 -Profile web`，将 `web` 替换为安装时使用的 Profile。手动运行的 MCP 可按上节单独关停。

普通卸载保留当前知识库配置，重装可继续读取。匠宝 `desktop` 使用 `harness\dsh-mcp-tbea-knowledge.json`。普通 Profile 与独立 MCP 使用 `config/local.json`。彻底清理配置由管理员单独操作。下方数据清理脚本适用于使用 `config/local.json` 的独立运行目录。

~~~powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Clear-LocalData.ps1 -WhatIf
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Clear-LocalData.ps1
~~~

自定义缓存目录需另传 `-DataDirectory "F:\实际缓存目录"`，路径须与配置一致。仅在确定要移除项目、凭证和启动配置时加 `-IncludeConfig`。清理缓存后，聊天正文仍保存在匠宝中，旧引用可能无法再次展开。

## 内网验收

本机验证覆盖 MCP、插件与浏览器展示。已用 Postman 提供的国别手册单库响应做本地回放，目标原文排在第一。正式平台、DSH 和内网 DeepSeek 的组合效果需要按下表实机确认。

| 验收项 | 检查方法 |
| --- | --- |
| 检索准确性 | 用乌拉圭原段落验证国别手册召回，再分别查询出差制度、PLM 和设计标准，核对切片、引用及耗时 |
| 触发路径 | 开启时直接问纯数学与公司标准。再对照问「供应商准入是什么意思？」和「公司供应商准入要交哪些材料？」，核对通用解释与内部依据是否区分。关闭时直接问公司标准应无检索记录，手动选中后应先检索并显示来源，取消后应恢复不查库 |
| 增库与撤权 | 新库授权并索引后，在下一轮目录刷新时参与检索。授权或描述变化时，核对新工具说明的摘要；撤权后验证对应旧切片和图片无法再次读取 |
| 图文与历史 | 用真实含图片及表格的切片核对排版和预览，退出重启后确认仍可打开获准的旧来源 |
| 会话引用与原文 | 在同一会话用两轮问题引用同一份 PDF，确认「引用文档」只列一份。点击文档名打开原文，再用「查看引用」分别返回两轮。升级后再打开旧会话确认历史引用 |
| 插件配置生效 | 在匠宝确认当前 Profile 为 `desktop`。用 `Doctor.ps1 -Desktop` 核对已安装版本和 Harness 根目录配置。在独立测试环境移走原解压目录后重启，确认检索及 PDF 预览仍可使用 |
| 异常与生命周期 | 验证部分超时的覆盖提示、全失败、空结果和用户停止。确认托盘完全退出后本机端口释放，打开匠宝后服务恢复 |

源码目录和开发命令索引见 [项目 README](../README.md)。
