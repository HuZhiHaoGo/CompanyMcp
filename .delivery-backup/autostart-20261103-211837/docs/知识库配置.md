# 知识库 ID 填写教程

当前**没有知识库管理界面**，由管理员编辑本机 `config/local.json`。聊天端只显示“公司知识库”，使用者无需选择具体库。

## 配置文件在哪

若工程位于 `F:\Code\dsh-mcp-tbea-knowledge`，配置文件就是：

```text
F:\Code\dsh-mcp-tbea-knowledge\config\local.json
```

若目录内只有 `example.json`，先在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Initialize.ps1
```

初始化生成服务口令和本地配置，不覆盖已有文件。源码目录和 `offline` 运行目录是独立实例；**应修改实际启动服务使用的那份 local.json**。插件的 `configFile` 必须指向同一份文件；初始化后可查看 `plugin/cordis.patch.yml` 中的路径。

## 知识库 ID 从哪里取得

使用公司平台管理页面已有的知识库 ID，或者你已验证成功的 Postman 检索请求里的知识库标识。按平台实际返回字段核对，必要时请平台管理员确认。

- ID 是平台真实标识，不是中文名称、文档 ID、切片 ID、项目 ID 或聊天应用 app_id。
- `total_count` 是检索到的切片数量，不能填写为知识库 ID。
- 本项目不自动拉取和同步平台知识库清单。凭证必须对登记的每个库具有检索权限。
- 示例 `demo-design`、`demo-plm` 只能用于演示，不能进入正式模式。

## 如何填写多个知识库

先停止知识服务，并完全退出 DSH Desktop。打开 `local.json`，找到 `knowledgeBases` 数组，按下面格式替换。以下仅为该数组的示例，**不要用它覆盖整个文件**：

```json
"knowledgeBases": [
  {
    "id": "替换为产品设计标准库的真实ID",
    "name": "产品设计原则与标准",
    "description": "产品设计要求、适用标准及技术条款"
  },
  {
    "id": "替换为PLM问题库的真实ID",
    "name": "PLM问题处理",
    "description": "PLM操作说明、常见故障及处理案例"
  }
]
```

| 字段 | 填写方法 |
| --- | --- |
| `id` | 必填，平台真实知识库 ID，各条不可重复 |
| `name` | 必填，管理员可读的库名称，用于来源卡片和模型工具说明 |
| `description` | 可选，便于维护的业务范围说明 |

JSON 使用英文双引号；两条对象间用英文逗号分隔，最后一条后不加逗号；文件内不写 `//` 注释。

同时将 `mode` 设为 `live`，填写 `platform.accessKey`、`secretKey`、`projectId`；固定地址保持 `https://ai.tbea.com`。保留原来的 `port`、`serviceToken`、`dataDirectory`、`limits` 和其他平台字段，具体见《使用教程》第五节。

保存后重新启动知识服务和 DSH Desktop。只改库清单也需要重启两者，确保服务的授权白名单与 DSH 的工具说明一致；目录未移动且插件路径未变时，无需重新安装插件。

## “检索全部”具体是什么意思

选中“公司知识库”后，程序向 `search_knowledge` 发送当前文字问题，**不传 `knowledge_base_ids` 限定项**；服务使用 `knowledgeBases` 中登记的全部 ID 作为检索范围。

例如登记两个 ID，就在这两个库中检索；增加第三个 ID 并重启后，范围才扩展到三个库。不会绕过授权，也不会搜索未登记的库。检索范围是全部登记库，返回结果仍受相关分数和 `limits.top` 条数限制，并非下载所有文档或每个库都必须返回一条。

模型自动调用工具时可以提出更小的已授权范围；服务仍校验白名单，不接受未登记 ID。人工选中后的程序预检索始终使用完整已登记范围。

## 验证和排错

1. 运行 `powershell -ExecutionPolicy Bypass -File .\scripts\Doctor.ps1`，检查配置与 MCP 握手。诊断不会自动发起正式资料检索。
2. 在 DSH 点击 `+ → 公司知识库`，等上方出现标签后，询问一条确定存在于已登记库中的问题。
3. 确认出现“已先检索公司知识库”，展开“参考来源”，核对文档、库名称、切片和图片。
4. 继续发送第二条问题，确认无需重新选择；点 `×` 取消后恢复模型自动判断。

| 情况 | 检查内容 |
| --- | --- |
| 正式模式不能使用演示 ID | 替换全部 `demo-` ID |
| ID 重复或缺少名称 | 修正 `knowledgeBases` 每个对象 |
| 401/403 | 核对 AK/SK、项目及各库权限，由平台确认错误；不盲目重发 |
| 一直无结果 | 确认 ID、业务资料、问题条件、重排模型与阈值；`top` 不是库数量 |
| 修改后没有变化 | 核对启动时实际读取的 local.json；重启服务及 DSH |
| 去掉某库后旧来源无法展开 | 服务按当前白名单禁止访问被移除库，属于授权校验 |

会话选中状态保存于 `data/dsh-selection`，不修改 `local.json`；同一会话持续有效，新会话默认未选中。备份/迁移历史时保留 `data`，日常修改库清单无需手动编辑这些状态文件。
