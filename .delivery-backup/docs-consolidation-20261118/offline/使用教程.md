# 安装与使用教程

## 一、交付范围与前提

- Windows x64，内网匠宝目标运行时为 **Harness 0.2.2-rc.1**，插件也接受 **0.2.2-alpha.2**。以终端的 `dsh --version` 为准。
- 已安装 DSH Desktop，内网模型已配置。模型需要支持工具调用，但不需要支持图片输入。
- 服务只读检索公司知识，不自动执行工作流或任意外部函数。
- 可先用 mock 模式验证；此模式不访问公司平台或任何模型。
- 完整 DSH Desktop 和公司接口联调需要在内网进行。本机完成的测试不等同于内网验收。

## 二、复制哪一个目录

**仅运行与试用：**复制 `offline/dsh-mcp-tbea-knowledge` 的全部内容，例如放到内网 `F:\Code\dsh-mcp-tbea-knowledge`。它包含 `runtime/node.exe`、已构建服务、已构建插件和脚本，无需下载依赖。

**继续开发：**复制整个源码工程，包括 `node_modules`、`package-lock.json` 和 `runtime`（若有）。离线 Windows x64 机器可直接构建；不要在没有缓存的内网运行 `npm ci`，该命令会删除现有依赖后重新安装。

`config/local.json` 是后续初始化生成的管理员配置；`data` 是后续使用产生的资料缓存。发布的离线运行包默认不携带这两类内容。已有历史记录迁移时，需额外迁移它们，不要将包含正式资料或凭证的目录对外分发。

源码工程若没有系统 Node/npm，可使用源码目录内附带的 `offline\dsh-mcp-tbea-knowledge\runtime\node.exe` 运行 `scripts/build.mjs`、`--test tests/*.test.mjs` 等命令；运行版脚本会自动查找附带的 Node。后续新增依赖仍需在外网准备后迁移。

## 三、初始化与独立演示

在复制后的项目目录打开 PowerShell：

```powershell
cd F:\Code\dsh-mcp-tbea-knowledge
powershell -ExecutionPolicy Bypass -File .\scripts\Initialize.ps1
```

初始化会生成随机服务口令和本项目的插件配置，不覆盖已有 AK/SK 和工作模式。移动项目后应重新初始化，并重新安装插件，使绝对配置路径更新。

正常使用DSH可直接继续第四节安装。新版知识服务随DSH Host自动启动，不需要额外运行服务脚本。

如需在安装前单独验证演示，可选运行下面命令，并在此阶段保持窗口运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Start-Service.ps1
```

在浏览器打开：

```text
http://127.0.0.1:17861/demo
```

点击“参考来源”，检查来源展开、`A*B*C` 表格内容、合并行表格、切片详情和图片；点击图片检查放大、缩小、恢复和关闭。演示资料不构成设计依据。

DSH已启动，或手动服务正在运行时，可另开终端运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Doctor.ps1
```

预期看到健康检查、MCP 握手和两个工具名称。正式模式下诊断工具不会自动检索公司资料，也不输出凭证。

## 四、安装到 DSH Desktop

1. 匠宝的 `desktop` Profile 由应用管理，初始化后通过内网已有的插件安装入口安装本构建产物。普通 `dsh` 命令会拒绝修改该 Profile。
2. 使用普通 Harness Profile 时，在对应终端进入项目目录执行：

```powershell
cd F:\Code\dsh-mcp-tbea-knowledge
powershell -ExecutionPolicy Bypass -File .\scripts\Install-Plugin.ps1 -Profile web
```

脚本会执行本地目录安装，带 `--offline --ignore-scripts`。使用其他普通 Profile 时，把 `web` 改成实际名称。

3. 升级时先结束旧版手动服务窗口，再从托盘**完全退出** DSH Desktop并重新启动；关闭窗口通常不等于退出。服务会随Host自动启动，后续普通启动无需重复安装，也不用运行Start-Service.ps1。
4. 在 DSH 新会话输入框点击 `+`，选择“公司知识库”；也可输入 `/company-knowledge`。**看到输入框上方的“公司知识库 ×”标签后再提问**，例如：

```text
查询演示设计要求，按表格整理，标明引用编号。
```

5. 选中来源后，Host 先通过真实 MCP 逐个查询当前授权范围内的知识库，再放行模型。打开“参考来源”可检查图文展示，同一证据的其他副本可从“其他来源”展开。部分库未完成时，来源卡片会显示已检索库数。
6. 标签按会话持续保留，发送多次问题或重启后仍生效；点击标签的 `×` 可取消。取消后仍可由模型自动调用检索工具，自动调用的来源显示在对应工具结果中。出现模型工具授权提示时，按 DSH 本地权限规则处理。

如果升级旧版插件，先按原目录执行 `Install-Plugin.ps1`，再完全退出并重启 DSH；不要覆盖既有 `config/local.json` 和 `data`。若离线安装仍解析旧产物，可在托盘终端先运行 `dsh plugin remove dsh-plugin-tbea-knowledge`，再运行安装脚本；这不会删除本项目的配置和资料缓存。实际命令执行结果需在内网确认。

自动启动默认启用，已有local.json无需新增字段。启动失败时，输入区显示原因及“重试启动知识服务”按钮；该按钮只恢复服务，不自动重发先前的问题。完整生命周期及可选手动模式见 [自动启动与排错.md](自动启动与排错.md)。

### 是否需要再安装通用 MCP 插件

不需要。本插件 Host 已内置标准 MCP 客户端，注册 `mcp__tbea__search_knowledge` 和 `mcp__tbea__get_chunk_detail`，同时将展示数据写入独立 `presentationMeta`。

若其他客户端只需要检索，可以连接标准 MCP 地址 `http://127.0.0.1:17861/mcp`，请求头为 `Authorization: Bearer <local.json 中的 serviceToken>`。其他客户端默认只能获得自身支持的展示效果，不会自动拥有本项目引用界面。

不要在同一 DSH profile 再配置一个 `serverName: tbea` 的通用 MCP 桥接，避免工具名冲突。

### profile 安装异常的排查

- `dsh` 不存在：从 DSH 托盘打开终端，而不是普通 PowerShell。
- `not-a-bundle`：确认已复制整个 `plugin` 目录，初始化已生成 `plugin/cordis.patch.yml`，且包中保留 `dsh.bundle.patch`。
- 版本不兼容：核实 Harness 是否为 `0.2.2-rc.1` 或 `0.2.2-alpha.2`。卸载及版本升级步骤见 [卸载与关停](卸载与关停.md)。
- 离线依赖缓存错误：本插件本身无安装依赖，但 DSH profile 已有依赖可能需要自身完整缓存；保留错误输出后补齐 DSH 安装，勿删除 `--offline` 后盲目重试。
- 安装成功但没有界面：完整重启；核对当前 profile 和插件启用状态；查看 Host 是否报告缺少 `tools`、`connection`、`agents`、`slots`、`commandUi`、`uiConversation` 或对应槽位。若只有引用卡片而无菜单，检查是否仍在运行旧版插件。
- 移动目录后仍读取旧配置：重新初始化、重新安装。若 profile 自己已有同 id 配置覆盖项，按 `config/generated-profile.patch.yml` 更新**对应条目**，不能覆盖整个 profile 配置文件。

## 五、切换正式知识库

完全退出 DSH 后，编辑正在使用的 `config/local.json`。新配置默认自动发现，旧静态配置需由管理员确认范围后再启用。修改或补充下面这些字段，其他项目配置如端口、服务口令和数据目录继续保留。

~~~json
{
  "mode": "live",
  "knowledgeDirectory": { "mode": "auto", "refreshSeconds": 60 },
  "platform": {
    "baseUrl": "https://ai.tbea.com",
    "accessKey": "填写现有AK",
    "secretKey": "填写现有SK",
    "projectId": "填写项目ID",
    "listPath": "/api/ai_apaas/v1/knowledgeBase?Action=DescribeKnowledgeBases",
    "searchPath": "/openapi/v1/knowledgeBase?Action=QueryKnowledge",
    "chunkPath": "/api/ai_apaas/v1/knowledgeBase?Action=DescribeChunk",
    "rerankModelName": "bce-reranker-base-v1",
    "rankScoreThreshold": 0.4
  }
}
~~~

- 自动模式按凭证可见范围拉取项目目录。确认该范围适合试用人员后再启用，必要时用静态模式限定库 ID。
- 内网 Postman 已确认 `QueryKnowledge` 的 `rerankModelName` 为必填，省略会返回 `KBIN04`。首版用 `bce-reranker-base-v1`，由平台内置检索执行重排。
- 每库默认最多取 3 条候选，合并后默认最多向模型提供 5 条证据；默认并发为 2。已有配置会自动采用新增检索参数默认值。调整位置见 [知识库配置](知识库配置.md)。
- 需要普通图片 Bearer 鉴权时，将 `assetAuth` 设为 `bearer`，并填写 `assetApiKey`。平台预签名图片沿用原链接，不附加 Bearer。

重新启动 DSH 后，用已知在知识库里的问题测试。正式模式下 `/demo` 返回 404。升级旧配置、静态范围及故障处理见 [知识库配置.md](知识库配置.md)。

## 六、使用习惯与准确性

- 必须先检索时，使用 原生 `+` 菜单或 `/company-knowledge` 选中“公司知识库”；选中时即使问天气也会先检索。未选中时，模型仍可按工具说明自动检索，但无法保证所有业务问题都触发。
- 来源标签的显示不包含具体库名，实际范围取决于自动目录或管理员设定的静态清单；菜单和候选项只设置开关，不在选择时访问公司检索接口。
- 每条新文字提问先检索原始问题；不调用模型改写问题，超过配置长度会明确报错。后续追问若省略产品等关键信息，请补充完整条件；模型仍可根据对话补充检索。
- 目录失败、全部库检索失败或用户停止时，强制检索模式下本次不交给模型回答，由用户决定是否重新发送。部分库未完成时，模型仅使用已有证据并说明覆盖不完整。全部库完成但没有相关结果时，模型应明确说明缺少依据。
- 标签取消仅影响后续处理，不能撤回已经发出的检索。停止当前检索请使用 DSH 停止请求功能。
- 模型使用返回的 `citationId` 标注出处。程序预检索来源位于对应上下文卡片，模型自动检索来源位于工具结果内；正文普通编号不会自动变为可点击链接。
- 复杂问题先补产品、地区、标准版本；结果为空不代表模型可以用常识代替公司规定。
- 图片仅供用户查看。文字证据不足时，模型不应声称已经读懂图纸。
- “切片详情”展示已保存的切片信息；旁边刷新按钮重新请求平台切片详情。其错误单独显示，不吞掉原结果。
- 图片点开来源后加载并缓存；签名过期会尝试刷新只读切片详情。已缓存图片可供历史查看，未缓存且平台无法刷新时会明确报错。
- 只支持 PNG、JPEG、WebP、GIF。表格支持 GFM 和 HTML 单元格合并；不运行切片脚本和任意 HTML。

## 七、内网验收清单

| 项目 | 预期 |
| --- | --- |
| MCP 工具可见 | DSH 能实际调用两个只读工具，不只是模型口头声称调用 |
| 来源入口 | `+` 菜单和 `/company-knowledge` 均能选择，标签只显示“公司知识库”；选择动作本身不检索 |
| 程序先检索 | 选中时每次新提问先完成 MCP；整体失败或停止时本次模型不回答 |
| 持续与取消 | 标签持续到取消，重启同一会话仍保留，新会话隔离；取消后自动工具仍可用 |
| 正式切片 | 乌拉圭问题应进入国别手册并引用正确原文；出差、PLM、设计标准查询分别核对对应来源 |
| 授权目录 | 新库完成索引和授权后，在下一次目录刷新后参与检索。撤权后无法访问该库的详情和图片 |
| 来源关联 | 文档名、知识库、切片 ID 与回答引用一致。合并证据的其他来源可独立查看 |
| 工程表格 | 星号、单位、多行单元格和合并行列保留 |
| 图片 | 预览、放大、关闭、下载；网络错误可重试 |
| 模型请求 | 不含图片字节、Base64、平台签名URL或AK/SK |
| 退出重启 | DSH 历史工具 meta 与本项目 data 快照能够重新关联 |
| 错误与停止 | 核对部分失败覆盖提示、全失败、空结果和停止。500 不自动重发 |
| 缓存与路径 | 更换目录后重做初始化；配额满时明确报错 |

若公司证书链不被 Node 信任，应按公司规范配置 `NODE_EXTRA_CA_CERTS` 指向公司 CA；不要关闭 TLS 校验。

## 八、卸载与后续开发

从 DSH Terminal 运行 `dsh plugin remove dsh-plugin-tbea-knowledge` 并完全重启客户端，本插件创建的知识服务随Host退出。若另外运行了手动服务窗口，则在该窗口按Ctrl+C停止。不要直接删除DSH整个profile。

卸载插件不删除本项目 `config/local.json` 和 `data`。保留这些文件可恢复历史；清理前先备份。

多人集中部署、知识库管理界面、回答正文引用跳转、公司工作流和中断恢复仍是后续扩展。
