# 验证记录与边界

本次开发以 Harness **0.2.2-alpha.2**、源码提交 `f3803c96974ad4a94195fb97e5c637e9c2a3afe3` 为接口依据。本机没有公司内网连接，也未安装运行完整 DSH Desktop。

## 0.6.0 逐库检索与覆盖状态

- 内网 Postman 对照中，原顺序同时查询 7 个库只返回规章制度，将两个国别手册放到最前则命中原文。单查两个国别手册均能找到原文，原顺序把 `top` 改为 20 仍未命中。
- 0.6.0 改为逐库检索。自动化测试覆盖目录换序、新库自动进入、重复来源、版本和图片差异、撤权过滤、部分超时、整体失败及用户取消。
- 使用提供的 Postman 响应做本地回放，两个国别手册使用真实单库响应，其余库的检索结果由样例模拟。目标国别手册原文排在首位。实际运行的跨库相关性与分数可比性仍需内网实测。
- 本机浏览器验证了窄窗口、主题、图片重试及表格，并验证部分覆盖提示、其他来源展开和部分检索无证据提示。

## 0.5.0 卸载与关停

- 对照匠宝使用的 Harness `0.2.2-rc.1` 校验插件版本声明，并确认普通 `dsh` 会拒绝操作专用 `desktop` Profile。实际匠宝界面卸载仍需内网验收。
- 36 项自动化测试通过，覆盖关停鉴权、配置和运行方式校验、暂停后避免重新启动、保留独立服务及恢复自动启动设置。
- 在临时普通 Profile 用原生 CLI 验证卸载后保留配置、缓存和开关。用模拟文件验证清理预览、按范围删除和显式删除配置。离线包验证独立进程可显式关停。

## 0.4.0 内网接口与实现边界

- Postman 已验证项目目录一页返回 7 个库、完整 ID 数组发送到 `QueryKnowledge`、平台接受 `bce-reranker-base-v1` 并能取到命中切片正文。
- 相同检索请求在旧路由曾返回 `InternalServerError`。省略重排模型名在新路由返回 `KBIN04`。
- 新实现的多页目录、到期刷新、弱相关过滤和旧引用授权，通过本地模拟接口验证。真实跨页、新库、含图切片、用户级权限及 DSH 与内网模型组合仍需验收。
- 本地 34 项自动化测试通过。离线运行目录通过无 npm 启动、MCP 握手、Host 自动启动与退出检查。浏览器演示验证了 `+`、`/`、表格、图片、浅深主题与窄窗口。旧配置迁移已另行验证，原文件保留，旧静态范围继续生效。

## 0.3.0 历史本机验证

0.3.0增加Host内自动启动、服务身份核对、实例去重、退出清理与失败重试；回归测试覆盖生命周期和既有检索、展示功能。完整DSH和内网服务仍需按下表联调。

本轮构建成功，33项自动化测试全部通过；浅深主题、390px及320px窄窗口、22px字号、控件尺寸、键盘焦点和边界状态检查通过。

0.2.1补充浅深主题、宿主自定义强调色、320px窗口与22px字号、控件尺寸、长标题、短多行正文、图片失败重试、空结果和弹窗键盘焦点检查。详见《界面适配检查.md》。

- 构建 Node 服务、诊断工具、Host 插件和浏览器模块工厂。
- 真实 MCP SDK 客户端与 HTTP 服务完成握手、工具发现、检索及详情调用。
- 模拟 Host 正式工具接口，验证模型文字投影和持久展示 meta 分离、私有数据不进入模型。
- 检查构建后的浏览器模块工厂、`tool.call.toolview` 注册名称和注入回调。
- 通过浏览器在1280×900和390×844视口检查来源展开、工程表格、切片详情、图片加载、放大、Esc关闭和刷新恢复；检查页面横向溢出和图片越界。
- 校验中国标准时间签名、500不重试、图片预签名不叠加Bearer、跨主机图片拒绝、图片类型校验、缓存恢复、授权范围移除和等待队列取消。
- 离线运行目录不依赖 node_modules，附带Windows Node.js；在独立目录验证手动服务与诊断后，停止手动进程，再由Host自动启动服务，完成真实MCP预检索并在退出后释放端口。
- 真实 MCP 测试确认：选中会话先检索全部登记库，多次新提问持续生效，工具续跑不重复检索，其他会话不受影响，取消后自动工具仍注册。
- 确认程序预检索等待真实结果，空结果记录实际证据，失败或取消不返回可入模决策，不伪造模型 tool call。
- 验证 `+`/`@` 使用同一来源开关、菜单浏览不检索、Host 确认后才显示选中；验证开关持久化、并发写入及损坏配置报错。
- 检查程序检索上下文的来源卡片节点可由持久消息恢复。
- 加载Host即自动启动，正常退出或进程直接退出后释放端口，再次启动恢复；中文空格路径及复制到模拟profile安装目录后仍可检索和展示演示页。
- 并发启动只创建一个同进程服务，最后一个使用者退出后关闭；手动服务只复用不关闭，其他进程管理的实例拒绝接管。
- 覆盖端口占用、旧版服务、不同口令/配置、无效缓存目录、启动中退出、关闭后重试及Windows UTF-8 BOM配置。
- 图片/切片共享任务中，单个调用者取消不影响其他调用者；全部取消后中断上游。
- 启动失败显示可读提示和重试；重试不自动发送旧问题。诊断核对版本、配置身份及鉴权，避免误连旧实例。
- 通过真实 MCP HTTP 验证停止信号会中断该次后端请求，同时其他会话的并行检索继续运行。

## 内网仍需验证

1. DSH Desktop 当前安装能否成功离线安装组合包，Host/browser 插件是否实际激活。
2. 当前内网模型是否实际发出工具调用，DSH权限设置是否允许只读工具。
3. 正式知识库检索/详情接口的路由、鉴权、响应字段和重排参数。
4. 平台图片鉴权、有效期、重定向策略及公司CA证书。
5. DSH完整会话历史回放及本项目缓存目录迁移后的恢复。
6. 检索相关性、引用准确性、正式表格/图片格式及实际并发负载。
7. `+` 和 `/` 命令在真实 Desktop 的位置、持续来源标签和历史预检索卡片显示；真实停止按钮的取消信号是否传播。
8. 通过内网模型服务请求日志确认：选中后 MCP 完成在模型请求之前，检索失败时没有本次模型请求；未选中时自动调用仍正常。
9. 安装当前版本后无需服务窗口即可使用，完全退出DSH后释放端口，再次启动恢复；内网终端策略、多个profile端口和公司CA设置符合实际环境。

以上待验证项未被演示数据、模拟Host或SDK协议测试替代，不能据本记录宣称已完成生产验收。
