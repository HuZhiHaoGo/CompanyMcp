# 随 DSH 自动启动 MCP

0.5.0 增加单独关停、关闭自动启动、卸载和显式数据清理。具体命令及保留范围见 [卸载与关停](卸载与关停.md)。

## 日常使用

插件安装到当前 DSH profile 后，只需正常打开 DSH。Host 加载插件时，会自动启动本机 MCP 服务，无需每次安装，也无需运行 Start-Service.ps1 或保持 PowerShell 窗口。

默认端口仍为17861，地址仍为127.0.0.1，只能在本机访问。启动过程只核对本地服务身份、准备缓存及监听端口，不检索公司资料、不调用模型。

关闭聊天窗口可能只是隐藏到托盘；从托盘完全退出DSH，Host结束后，本插件创建的服务也随之结束。MCP运行在Host进程中，没有另起隐藏Node子进程；Host进程意外退出时也不会遗留独立服务进程。再次打开DSH会重新启动，已有本地记录和来源快照保留。

## 从旧版升级

1. 完全退出DSH，并关闭旧版 Start-Service.ps1 服务窗口。旧版服务仍占用端口时，新插件会明确提示，不接管或杀掉占用进程。
2. 更新项目文件，保留原 config/local.json、data 和正式凭证。
3. 按 [使用教程](使用教程.md) 更新插件。匠宝的默认 `desktop` Profile 沿用内网安装入口。普通 Harness Profile 可在项目目录运行：

```powershell
cd F:\Code\dsh-mcp-tbea-knowledge
powershell -ExecutionPolicy Bypass -File .\scripts\Install-Plugin.ps1 -Profile web
```

4. 从托盘完全退出并重新启动DSH。初始化会更新本插件的绝对配置/资源路径，不覆盖已有local.json。
5. 通过 `+` 菜单或 `/company-knowledge` 选择“公司知识库”，看到来源标签后提问。后续普通启动DSH无需重复执行安装或启动脚本。

升级代码、移动项目目录或切换profile时需要重新安装；只是重启电脑或重启DSH不需要。

## 配置与手动模式

已有local.json不增加字段也会默认自动启动。新建配置包含下面的可选项：

```json
"service": { "autoStart": true }
```

这是字段片段，不是整个配置。改为false并完全重启DSH后，插件仅连接已运行的服务，不自动创建监听器；适合需要独立运行服务的管理员。

独立运行命令仍保留：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Start-Service.ps1
```

如果已经有新版手动服务，且口令、配置和版本完全一致，DSH可以复用它；退出DSH不会关闭管理员手动启动的服务。手动服务由原窗口Ctrl+C停止。

不要在DSH已经自动启动服务后，再重复运行手动启动脚本。端口不会自动漂移，避免客户端连接错实例。

## 失败提示与重试

输入区会显示服务启动失败原因，并提供“重试启动知识服务”按钮。修复原因后点击即可；按钮只恢复服务，不自动重发旧问题。之前失败的提问需要用户重新发送。

| 提示 | 处理方法 |
| --- | --- |
| 旧版/不同版本服务 | 关闭旧服务窗口，再完全重启DSH |
| 其他程序占用端口 | 确认占用者；关闭该程序，或修改local.json的port并重启DSH |
| 服务口令不同 | 确认两个实例是否读取同一份local.json，不盲目复制覆盖凭证 |
| 服务配置不同 | 核对知识库清单、平台参数、数据目录等；重启旧服务或使用不同端口 |
| 另一个DSH进程管理 | 同一电脑的独立profile/Host进程应使用独立配置、端口和data目录 |
| dataDirectory不可写 | 检查目录权限及路径；不能把普通文件路径当作目录 |
| 本机网络权限 | 按公司终端策略允许本机监听和访问127.0.0.1；不要改为监听所有网卡 |
| JSON格式错误 | 检查英文双引号、逗号、括号；最外层应为对象。支持Windows UTF-8 BOM文件 |

普通网络失败、平台500或模型请求失败都不会自动重发用户检索或业务操作。只读健康接口在遇到刚关闭的失效连接时允许重查一次，用于恢复启动状态。

## 多窗口和退出

同一Host进程中，相同配置的多个插件使用者会共用一个监听实例，并等待最后一个使用者释放后关闭，避免重复启动和误停。

多个独立DSH Host进程不共享由其中一个Host管理的服务，避免一个进程退出时影响另一个。每个独立实例使用不同端口和data目录；不同电脑可以使用相同的本机端口。

完全退出会停止正在进行的本机请求。正常对话中停止一条请求，不应影响其他会话；同时查看同一图片/切片时，一个窗口取消只取消自己的等待，所有等待者都取消后才中断共享请求。

## 诊断与验收

先打开DSH，再运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Doctor.ps1
```

诊断核对服务版本、配置身份、鉴权与真实MCP握手。正式模式不自动检索资料，也不输出AK/SK或服务口令。

当前本机验证覆盖自动启动、正常/直接进程退出、重启恢复、并发加载、端口冲突、旧版服务、配置不一致、启动失败与重试、中文空格路径、复制到profile目录后的加载，以及独立离线包。

完整DSH Desktop和公司内网仍需实机联调；请在内网确认只打开DSH即可提问、托盘完全退出后端口释放、再次启动历史来源可展开，并核对正式接口、证书、模型权限和检索质量。
