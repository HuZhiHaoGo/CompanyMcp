# 知识库配置

在项目或离线运行目录中打开 `config/local.json`。如果只有 `config/example.json`，从项目根目录运行以下命令生成本地配置。

~~~powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Initialize.ps1
~~~

初始化保留已有配置和凭证。源码目录和离线目录是独立实例，修改插件 `configFile` 指向的那份文件。修改配置后完全退出并重启 DSH。使用独立服务窗口时同时重启独立服务。

## 自动发现

新配置的 `knowledgeDirectory.mode` 默认为 `auto`。正式调用时，在 `local.json` 中设置 `mode` 为 `live`，填写 `platform.accessKey`、`platform.secretKey`、`platform.projectId`，并保留已验证的 `platform.rerankModelName` 值 `bce-reranker-base-v1`。聊天应用的 `app_id`、API Key 与纯知识检索无关。

~~~json
"knowledgeDirectory": {
  "mode": "auto",
  "refreshSeconds": 60
}
~~~

这是配置片段。自动模式使用配置凭证和项目 ID 调用 `DescribeKnowledgeBases`，逐页获取目录，再为目录中的每个库单独调用 `QueryKnowledge`。静态 `knowledgeBases` 用于演示或手工限定范围。已有演示数组可保留，正式自动模式只使用平台返回的真实库 ID。

服务首次需要目录时拉取，到期后在下一次检索、引用详情或图片访问时刷新。平台新库完成授权与索引后，可在下一轮刷新进入搜索范围。目录请求失败或没取全时会报告错误，服务不会用不完整的 ID 列表继续检索。被移出目录的库，在刷新后无法再通过旧来源打开切片或图片。

**管理员须先确认该凭证能列出的库都适合向这台电脑的使用者开放。** 目录范围基于配置的凭证和项目。本版面向个人试用，多人角色和文档级访问策略应在集中部署前另行确认。

## 静态范围与旧配置升级

旧配置如果已有 `knowledgeBases` 数组且没有 `knowledgeDirectory.mode`，升级后沿用旧清单。管理员确认可开放整个项目后，在 `local.json` 中加入上面的自动发现片段。需要继续限定部分库时，可显式设为 `static`，并保留至少一个真实库，例如：

~~~json
"knowledgeBases": [
  { "id": "平台真实知识库ID", "name": "产品设计标准" },
  { "id": "另一个真实知识库ID", "name": "PLM问题处理" }
]
~~~

`id` 对应列表中的 `data[].id`，`name` 用于显示。检索响应的 `total_count` 是切片数，列表响应的 `total` 是知识库数。库列表与项目 ID 是两个不同字段。

升级时，旧检索路径 `/api/ai_apaas/v1/knowledgebases/query` 会在读取配置时切换为已联调的 `/openapi/v1/knowledgeBase?Action=QueryKnowledge`。已有 `local.json` 的内容会原样保留，管理员可以对照新版 `config/example.json` 更新其中的路径文字。正式模式需要非空 `platform.rerankModelName`。

## 召回与验收

- `retrieval.perLibraryTop` 默认 3，是每个库的候选上限。单库实际请求值取它与 MCP 本次 `top` 的较小值。`limits.top` 仍作为 MCP 工具省略 `top` 时的默认值（10）。最终证据条数同时受本次 `top` 和 `limits.maxEvidenceChunks`（默认 5）约束，不要求填满。
- 平台检索并发上限为 2，两次发起至少间隔 150 毫秒。可选配置 `retrieval.libraryTimeoutMs` 默认 8000，指单库开始请求后的超时；`retrieval.roundTimeoutMs` 默认 30000，涵盖目录、排队及平台请求。上述 `retrieval` 字段可直接添加到 `local.json` 顶层。旧部署省略它们即可使用默认值。
- 同一轮沿用平台 `bce-reranker-base-v1` 和 `platform.rankScoreThreshold`（默认 0.4）。MCP 按平台有效分数合并，无有效分数时按稳定顺序处理。当前没有独立的跨库重排服务，跨库分数和阈值应使用内网业务样例评估。
- 同名文档的正文和表格等价、图片标识及图注一致且没有可识别的版本差异时，模型只收到一份文字证据。其他切片仍可在来源卡片展开，核对各库和文档的具体详情。共享段落但周边内容不同的切片分别保留。
- 知识库入口用 DSH 原生 `+` 菜单或 `/company-knowledge` 选择。选中后，程序先检索再回答。取消标签后由模型依据问题决定是否调用工具。
- 用乌拉圭样例复测逐库召回，再补测出差、PLM、设计标准和图表问题。内网 Postman 已对照验证原顺序、换序和国别手册单库响应。真实 DSH 从检索到回答、真实多页目录、新库入列和图片加载仍需内网验收。
- 如遇鉴权、目录空或分页失败，检查服务读取的 `local.json`、项目和凭证范围。避免为了排错临时扩大授权范围。可先运行 `scripts/Doctor.ps1` 查看配置和 MCP 握手状态。
